# WORK VITAL 카피·UX 라이팅 가이드

## 1. 라이팅의 목적

사용자가 다음 질문에 답할 수 있도록 돕습니다.

- **나에게 필요한 서비스인가?**
- **어떤 일을 도와주고, 무엇을 얻을 수 있는가?**
- **왜 이 서비스를 사용할 만한가?**
- **다음에는 무엇을 하면 되는가?**

핵심 독자는 조직 진단을 검토하는 **인사·조직개발 담당자**로 가정합니다. 이는 현재 화면에서 추정한 사용자이며, 실제 고객 확인을 통해 보완합니다.

문구는 이들이 겪는 어려움과 하려는 일을 출발점으로 작성합니다.

## 2. 카피 작성 원칙 — 5가지

### ① 고객의 문제와 이점을 먼저 설명합니다

기능이나 서비스 분류를 소개하기 전에 고객이 겪는 상황과 얻을 수 있는 도움을 설명합니다.

**피할 예**  
“진단에서 개선까지, 조직 활력 플랫폼”

**권장 예**  
“진단 결과를 받고도 무엇부터 개선할지 막막한가요? 부서별 결과를 비교해 개선 과제의 우선순위를 정하세요.”

**작성 기준**

- 주요 소개 문구에서 누구의 어떤 상황을 돕는지 드러냅니다.
- 기능을 설명할 때는 고객의 업무와 판단에 어떤 도움이 되는지 연결합니다.
- 고객이 기능명을 읽고 이점을 직접 추론하게 하지 않습니다.

### ② 짧고 구체적으로 씁니다

한 문장에는 하나의 중심 메시지를 담습니다. 추상적인 표현은 실제로 하는 일과 확인할 수 있는 결과로 풀어 씁니다.

**피할 예**  
“보이지 않던 조직의 상태를 가시화하고, 개선과 확인을 되풀이하여 몰입이 높은 조직을 만들어 갑니다.”

**권장 예**  
“구성원 설문으로 조직 상태를 파악합니다. 개선 활동 후에는 무엇이 달라졌는지 확인합니다.”

**작성 기준**

- ‘활력’, ‘가시화’, ‘개선’이 무엇을 뜻하는지 구체적으로 설명합니다.
- 의미를 더하지 않는 수식어와 반복 표현을 덜어냅니다.
- 짧게 줄이면서 대상·조건·중요한 정보를 빠뜨리지 않습니다.
- 한 번 읽고 핵심 내용을 설명할 수 있도록 씁니다.

### ③ 사용자가 이해하는 언어로 씁니다

전문용어는 고객의 업무에서 사용하는 말로 설명합니다. 필요한 공식 용어는 쉬운 뜻과 함께 사용합니다.

**피할 예**  
“회차별 종단 추이와 속성별 횡단 차이를 교차 분석합니다.”

**권장 예**  
“지난 조사와 비교해 변화를 확인하고, 부서·직급별 차이를 살펴봅니다.”

**작성 기준**

- 독자의 사전 지식 없이도 핵심 의미를 이해할 수 있어야 합니다.
- 전문용어가 필요하면 첫 등장에 뜻을 설명합니다.
- 같은 개념에는 같은 용어를 사용합니다.
- 전문성은 측정 범위·활용 방법·근거를 정확하게 설명해 전달합니다.

### ④ 다음 행동을 분명하게 안내합니다

버튼과 주변 문구는 사용자가 누른 뒤 실제로 하게 될 일을 알려줍니다.

**피할 예**  
“자료 받기”

**권장 예**  
“소개서·결과지 샘플 신청”

**보조 설명**  
“신청한 자료를 이메일로 받아보세요.”

**작성 기준**

- 신청·열람·선택·다운로드·결제를 구분합니다.
- 버튼에는 핵심 행동을, 주변 설명에는 필요한 조건과 절차를 담습니다.
- 행동을 요청하기 전에 사용자가 그 행동을 할 이유를 이해하도록 돕습니다.
- ‘지금’, ‘바로’, ‘무료’는 실제 조건과 맞을 때 사용합니다.

### ⑤ 확인된 사실로 선택의 근거를 제공합니다

막연한 우위나 효과 대신 고객의 판단에 필요한 범위·시간·조건·결과물을 구체적으로 설명합니다.

**피할 예**  
“가장 빠르고 정확한 조직 진단”

**권장 예**  
“워크바이탈 핵심형 본조사는 78문항이며, 약 15분이 걸립니다.”

**작성 기준**

- 숫자는 고객의 선택에 도움이 될 때 사용합니다.
- 수치에는 적용 대상·기준·기간을 필요한 만큼 함께 제시합니다.
- 실제 성과, 가상 예시, 기대 효과를 구분합니다.
- 기능 제공과 효과 보장을 구분합니다.
- ‘가장’, ‘정확한’, ‘검증된’ 등의 표현은 뒷받침할 근거가 있을 때 사용합니다.

## 3. 문장 표현의 세부 규칙

### 누가 무엇을 하는지 드러냅니다

사용자·담당자·시스템의 행동을 구분해 씁니다. 능동형을 우선하되, 결과나 상태를 전달하는 데 수동형이 더 명확하면 유지합니다.

‘됐어요’를 모두 ‘했어요’로 바꾸거나, ‘~었’을 일괄 삭제하지 않습니다. 시제와 의미를 보존합니다.

### 명사 나열을 행동으로 풀어 씁니다

**피할 예**  
“기대×만족 우선순위 도출”

**권장 예**  
“기대는 높지만 만족은 낮은 항목을 찾아, 먼저 개선할 과제를 정합니다.”

‘분석·도출·관리·지원’만 나열하지 않고 무엇을 분석하고 어떤 일을 돕는지 설명합니다. 제목·버튼·표 항목처럼 짧은 이름이 필요한 곳에는 명사형을 사용할 수 있습니다.

### 과도한 경어를 줄이고 자연스럽게 묻습니다

**피할 예**  
“혹시 이런 상황이 반복되고 있지 않으신가요?”

**권장 예**  
“설문 결과를 받고도 무엇부터 개선할지 막막한가요?”

‘~시’, ‘계시다’, ‘여쭈다’ 등을 기계적으로 삭제하지 않습니다. 필요한 정보와 상황을 중심으로 문장을 다시 씁니다. 정중한 요청이 필요한 맥락에서는 경어를 유지합니다.

### 말투를 일관되게 사용합니다

해요체·합니다체는 브랜드 말투에 맞춰 정하고, 같은 역할의 문구에 일관되게 적용합니다.

해요체 전면 적용을 필수 기준으로 두지는 않습니다. 버튼·제목·항목명까지 억지로 문장형으로 만들지 않습니다. 어미만 바꾸면서 추상적인 의미를 그대로 남기지 않습니다.

### 제한과 부정적인 사실도 정확하게 전달합니다

사용할 수 없는 기능, 공개하지 않는 결과, 종료된 기간은 명확하게 설명합니다. 필요한 이유와 가능한 다음 행동도 함께 안내합니다.

친근하거나 긍정적으로 보이기 위해 중요한 조건을 흐리지 않습니다. 안심을 주는 문구도 확인된 처리 방식과 조건을 근거로 작성합니다.

## 4. 문구의 역할에 따라 적용합니다

모든 문장에 대상·문제·이점·행동을 반복해서 넣을 필요는 없습니다.

| 문구의 역할 | 우선 전달할 내용 |
|---|---|
| 서비스 소개 | 누구의 어떤 문제를 어떻게 돕는지 |
| 진단·기능 설명 | 무엇을 확인하고 어떤 판단에 활용하는지 |
| 결과·사례 설명 | 무엇이 실제 결과이고, 어떤 기준으로 해석하는지 |
| 비용·이용 조건 | 금액·기간·대상·포함 범위 |
| 버튼·링크 | 누른 뒤 실제로 하게 될 행동 |
| 안내·오류 문구 | 현재 상태와 사용자가 할 수 있는 다음 행동 |

## 5. 검토 체크리스트

문구의 역할에 해당하는 항목을 **충족·부분 충족·미충족·해당 없음**으로 판단합니다.

- [ ] 독자가 자신에게 필요한 정보인지 알아볼 수 있는가?
- [ ] 무엇을 돕고 어떤 결과를 얻는지 구체적인가?
- [ ] 기능이 고객의 업무나 선택에 필요한 이유와 연결되는가?
- [ ] 전문용어의 뜻을 몰라도 핵심 내용을 이해할 수 있는가?
- [ ] 문장과 문단의 중심 메시지가 분명한가?
- [ ] 다음 행동과 필요한 조건을 예상할 수 있는가?
- [ ] 수치와 효과 표현이 확인된 근거의 범위 안에 있는가?
- [ ] 용어·말투·표현 방식이 일관되는가?

문제를 기록할 때는 다음 형식을 사용합니다.

**원문 → 이해·판단·행동이 어려운 이유 → 적용할 원칙 → 수정안**

‘어색하다’, ‘더 자연스럽다’라는 인상만으로 수정하지 않습니다. 취향에 따른 제안은 이해나 행동상의 문제와 구분합니다.

섹션 재배치·페이지 분리 등은 구조 개선 사항으로 별도 기록합니다. 문구 수정으로 기대하는 사용자 효과는 검증 전까지 가설로 표시합니다.
